# 核心设计（草案 v0.1）

依据：ADR-0001（极薄宿主）、ADR-0002（运行时装载与整体替换）、ADR-0003（机制级权限）、ADR-0005（权限插件化）。目标：Android 与桌面同时推进；语言 Java（尽量满足）；先完成核心，再逐个插件。

## 核心的对外职责（回顾）

装载、隔离与卸载；热装载管理；权限校验原语（极薄闸门：仅转发，决策由权限插件承担）；事件与钩子调度；参数存储原语；显示与输入外壳。不含玩法、时间与存档（存档=存档插件）。

## 模块草案（名称均为暂定）

1. **插件清单（Registry）**：记录已装插件、机制索引（机制 ID → 插件）、钩子索引、依赖与冲突信息。接口方向：install / remove / findMechanism(id)。
2. **装载器（Loader，跨端两个实现）**：桌面＝每个插件一个类加载器（JAR）；Android＝每个插件一个 dex 类加载器；负责签名校验与完整性检查、类空间隔离。接口方向：load(pluginPackage) / unload(pluginId)。
3. **热装载管理器（SwapManager）**：drain 流程（停止接受新请求 → 等待执行完成 → 替换 → 恢复）；数据按机制 ID 归属，不断档。接口方向：replace(pluginId, newPackage)。
4. **权限闸门原语（PermissionBroker 等）**：核心只保留极薄原语——插件来源（PluginOrigin：系统 / 三方）、操作请求（PermissionRequest）、闸门接口（Gatekeeper）、转发器（PermissionBroker）与用户提示通道（UserPrompt）；放行决策与用户提示由独立的权限系统插件承担。非系统插件的跨边界操作经闸门转发；无闸门时 fail-closed。
5. **调度器（Dispatcher）**：事件总线 + 钩子触发；动作 → 逻辑分发；逻辑相关代码在单一“逻辑线程”上串行执行（2026-09-13 落地：LogicThread；钩子调用、事件分发与生命周期操作均在其上派发）。
6. **参数存储（ParamStore）**：实例/机制参数的基础读写与变更通知原语；不做参数语义（结构由插件定义）。
7. **外壳（Shell，跨端两个实现）**：提供画布/视图宿主与输入事件转发；UI 插件在此接缝上与核心对接。具体渲染载体待插件细谈。

## 运行与工程形态（草案）

- 仓库结构：Gradle 多模块：core（纯 Java）、shell-desktop、shell-android；系统插件模块（system-plugins/）已加入。
- 进程模型：单进程；逻辑线程承载钩子调用、事件分发与插件生命周期操作（M3 收尾落地）；跨线程任务后续细化。
- 插件打包格式：桌面 JAR / Android dex；清单与签名格式待“插件细谈”后定。

## 里程碑（建议）

- **M0 运行骨架**：能装载一个最小测试插件并调用其机制（桌面跑通；Android 同步搭起骨架）。
- **M1 热替换**：drain 替换 + 数据不断档。
- **M2 权限**：闸门原语 + 权限系统插件（跨边界操作拦截、用户放行提示、无闸门 fail-closed）。
- **M3 调度 + 参数存储最小实现 + 外壳最小实现**。

存档、时间、UI、动作等由各系统插件在核心之后实现，不属于核心里程碑。

## 实施进展

2026-09-13：M0 运行骨架跑通；M1 热替换（drain + 数据不断档）完成并有单元测试覆盖；M2 权限完成（权限为独立系统插件）。

工程方面，仓库现有十个模块：core（纯 Java，Java 11 语言级别）、shell-desktop（命令行演示外壳）、shell-android（Android 应用骨架）、examples/demo-plugin 与 examples/demo-plugin-v2（热替换演示插件）、examples/neighbor-plugin（三方插件权限演示）、system-plugins/permissions-plugin（权限系统插件）、system-plugins/time-plugin、system-plugins/hooks-plugin、system-plugins/action-plugin（运转组系统插件：时间 / 钩子管理 / 动作）；Gradle Wrapper 指向 9.6.1，Android 侧使用 AGP 8.9.0。

M0 已实现：插件装载（每插件一个 URLClassLoader，读取 META-INF/lifeloom-plugin.properties 清单）、机制与钩子注册（机制 ID 与钩子 ID 全局唯一性校验）、按钩子 ID 调用钩子、插件卸载（onUnload、注册清理、类加载器关闭）、装载失败时的回滚。

M1 已实现：热替换 replacePlugin（drain：停止接受新的执行请求 → 等待执行完成 → 卸载旧版本 → 装载新版本 → 恢复），替换前预检新包并校验包 ID，激活失败时回滚旧版本；机制状态（MechanismState，按机制 ID 归属的键值数据，独立于插件注册生命周期，卸载与替换均不清除）保证数据不断档；执行闸门拒绝执行中的替换与替换中的新调用。单元测试 9 个全部通过；桌面演示 v1 → v2 升级通过。

M2 已实现：按修正，权限不是核心内建，而是独立系统插件。核心只保留极薄原语：PluginOrigin（系统 / 三方）、PermissionRequest、Gatekeeper（闸门接口）、PermissionBroker（转发器：系统插件与核心不受限；非系统插件经闸门，全部闸门放行才放行；无闸门 fail-closed；闸门随其注册插件卸载 / 替换而移除）、UserPrompt（外壳注入的用户提示通道，缺省全部拒绝）。接入点：插件访问他方机制状态（stateFor）与调用他方钩子（invokeHookFrom）经闸门；插件自身操作不经闸门（属自身权域，后续按需扩展闸门覆盖范围）。system-plugins/permissions-plugin（权限插件，系统来源）注册闸门，未决请求经用户提示询问并按（发起方，操作，目标）记忆决定；examples/neighbor-plugin（三方）验证拦截。单元测试共 21 个全部通过（新增权限转发器 7 个、权限集成 5 个）；桌面演示：无权限插件 fail-closed、有权限插件提示放行 / 拒绝、热替换回归。

M3 起步（2026-09-13）：调度与参数存储原语。调度：事件总线（EventBus）——插件可发射 / 订阅事件，订阅随插件卸载 / 替换自动解除；分发同步、异常隔离；发射经执行闸门（替换期间拒绝新发射、替换等待在途派发）。参数存储：ParamStore——按命名空间保存字符串键值、带变更通知（监听随插件卸载解除）；机制状态改由机制命名空间承载，数据不断档语义保持；新增 PluginContext.watchState（聆听机制状态变更，他方机制经权限闸门）。单元测试共 29 个全部通过（新增事件总线 5 个、状态监听 3 个）。单逻辑线程模型与外壳完善随后继续。

M3 收尾（2026-09-13）：单逻辑线程模型——钩子调用、事件分发与插件生命周期操作由 LogicThread 串行执行（调用方同步等待、线程内内联、drain 计数含排队中的派发）；插件间调用协议——钩子调用带输入输出，钩子解析器支持禁用与替代（解析链限长防环，见 ADR-0006）；外壳完善——--invoke（带输入 / 输出）、--emit、--state、--watch，收尾关闭逻辑线程。单元测试共 44 个全部通过（新增逻辑线程 5、派发路由 3、调用协议 7）。

运转组系统插件 v1（2026-09-13）：时间插件（游戏时钟——now / advance / set-scale 与 advanced 事件；无动作则静止、由动作驱动）、钩子管理插件（disable / enable / replace / restore / status，经核心钩子解析器生效，见 ADR-0006）、动作插件（register / can / execute / status；执行 = 动作逻辑 + 时间驱动，见 ADR-0007）。三插件单元测试合计 28 个全部通过；核心新增 Hook.of 便利工厂（从函数构造钩子，含 3 个测试，核心测试合计 47 个）；桌面外壳演示覆盖：动作注册 → 执行推进时钟 15 分钟 → 禁用跳过 → 恢复 → 替代到新钩子。

Android 侧已能构建出调试 APK，dex 中包含核心库类；Android 端插件装载器（DexClassLoader）与插件格式适配待 M0 后续加入。插件清单暂定为 properties 格式（新增 origin 字段辨识系统 / 三方，当前为清单声明占位，随签名机制接入后改为签名判定），打包与签名格式待“插件细谈”后确定。

## 未决点

- 插件打包/签名/清单的具体格式（等插件细谈）；签名辨识系统 / 三方与完整性校验。
- 闸门覆盖范围（哪些操作纳入放行清单）与声明式授权（安装期声明），随插件细谈细化。
- 机制休眠期（所属插件未装载）的状态访问归属校验。
- 声明式 UI 的目标实现与渲染载体。
- 桌面/Android 外壳的具体技术（窗口、输入、渲染）。
- 编译与 CI 环境（先跑通“能构建 core + 两个外壳”）。
