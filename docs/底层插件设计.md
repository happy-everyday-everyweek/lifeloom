# 底层插件层设计（草案 v0.3 · 2026-09-13）

Lifeloom 的底层（系统）插件层：位于核心与一切内容之间，只提供标准化能力，不含任何玩法。本层是上层一切玩法插件与三方插件的公共契约。

## 原则

- 只提供标准化能力（接口、格式、原语），不回答“玩什么”；具体动作、行为、界面、目标全在上层。
- 每个成员要小、职责单一；层内只走公开接口，任何一块都能单独替换。
- 成员自身也是普通插件：可装载、可整体替换、数据不断档；来源为系统，不受权限闸门限制。
- 先定本层接口，再定上层；核心原语（调度、参数存储）按本层需要设计。

## 成员（14 个 · 四组）

### 运转组

- **钩子管理**：钩子的管理者——注册检查、冲突检测、禁用与替代的登记（支撑“禁用原钩子+新建钩子”的推荐改法）；与核心调度的衔接口径已定——钩子解析器（见 ADR-0006）。
- **动作**：动作模型与执行的主理——动作注册、可执行判定、排队与打断、驱动时间轴、弹性动作的输入声明。不含具体动作。
- **时间**：游戏时钟的持有者——无动作则静止，由动作驱动流逝，含倍率。独立成员。

### 世界组

- **实例**：世界对象模型——实例创建、分类（人/动物/物品）、种、生命周期、实例间关系（容纳、持有）；“被体验实例”登记也归它。
- **参数**：参数系统——注册、基础与派生、派生计算与变更通知；可附着于实例与机制。判定规则的家：派生计算归参数、判定入口归动作。
- **地图**：空间模型——地点、地点间关系、实例的位置归属；给界面提供空间数据。不含出行玩法。
- **NPC**：非玩家实例的智能调度——上下文感知决策：收集上下文（NPC 状态、周围环境、世界状态）→ 决策 → 动作送进动作系统统一执行；与时间严格同步；AI 辅助（经 AI 插件）作为“聪明”的手段之一。
- **存档**：世界的保存与恢复——格式与版本兼容；参与式接口（各插件登记需保存/恢复的数据；机制状态天然在内）。

### 界面与服务组

- **UI**：标准化声明式 UI 的定义者与桥——描述格式、控件集、与核心外壳的渲染衔接；含通知标准件（给玩家的非阻塞提示）。系统插件直接用；三方间接，或经权限直接用。
- **AI**：AI 请求的唯一出入口——用户配置的服务端与密钥只存这里，其他插件只递请求，三方接触不到密钥。
- **跨端流转**：存档、插件与远程访问的端间流转——同一局域网下要求即时流畅；细节后置。

### 治理与工具组

- **权限**：放行与提示的闸门实现者（M2 已实现）；含权限管理面——已授权查看与撤销、决定记录；安装期声明确认与“插件管理”协作。
- **插件管理**：面向用户的插件控制台——安装、卸载、更新、启停；冲突与依赖提示；权限声明与确认入口。底层动作由核心装载原语完成。
- **调试工具**：开发与排障——注册表/机制/钩子查看、手动调用钩子、热替换、状态诊断。

## 连接关系

动作驱动时间；NPC 与玩家的动作走同一条动作流；实例与参数构成世界对象模型；地图给位置；UI 收界面、发通知；存档收状态；跨端流转搬端；权限横切所有跨边界操作；插件管理管生命周期；调试工具贯穿全层。

## 边界（写死）

本层只回答“怎么动、存在哪、怎么看见、怎么搬走”，不回答“玩什么”。具体动作、具体行为、具体界面、具体目标全在上层。

## 口径（不单立成员的事项）

- **素材/资源**：各插件自带素材、自身读取；跨插件引用按权限。先定约定。
- **设置/配置**：设置的界面归 UI 标准件，存放归各插件机制状态。
- **开局**：新档创建“自身”人实例 → 进入 → 放置；登记归“实例”，流程由实例+存档+UI 协作。

## 未决点

- 存档参与式接口的具体形式；装配口径（装载顺序与依赖声明）；各成员内部细节随逐组细谈。
- 签名、清单扩展、冲突检测、安装期声明等，随后续里程碑接入。

## 实施进展（2026-09-13）

运转组三个成员 v1 已落地（均为系统插件、含单元测试；桌面外壳可演示全链路）：

- **时间**（`dev.lifeloom.time`）：游戏时钟——`now` / `advance` / `set-scale` 钩子与 `advanced` 事件；无动作则静止、由动作驱动，倍率仅记录（供时间映射方）。
- **钩子管理**（`dev.lifeloom.hooks`）：禁用与替代的登记——`disable` / `enable` / `replace` / `restore` / `status`，经核心钩子解析器生效（见 ADR-0006）；注册期检查与冲突检测随清单 / 签名接入。
- **动作**（`dev.lifeloom.actions`）：动作模型——`register` / `can` / `execute` / `status`；执行 = 动作逻辑 + 时间驱动，v1 同步原子（见 ADR-0007；排队与打断、弹性声明、实例附着后置）。
