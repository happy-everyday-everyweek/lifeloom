# 动作模型 v1：注册、判定入口与时间驱动

动作是“附着在实例上的交互入口；本质是钩子，触发逻辑并修改参数”（词表）；执行动作时，游戏内时间按动作声明的时长流逝（ADR-0004）。运转组“动作”插件承担动作模型与执行的主理。本 ADR 固定其 v1 口径。

决策一（注册与身份）：动作 ID 即其钩子 ID（“动作相当于钩子”）；登记内容为动作时长（分钟，非负整数）。登记经动作插件钩子 `dev.lifeloom.actions.register`（输入 `id=<动作ID>;minutes=<分钟>`；重复登记即覆盖），任何插件均可调用（三方经权限闸门）。

决策二（判定入口）：可执行判定归动作插件（`dev.lifeloom.actions.can`）；v1 规则为“已登记即可执行”。依赖参数与实例的完整判定规则随参数、实例成员接入。

决策三（执行与时间驱动）：执行 = 调用动作同名钩子（逻辑）→ 按声明的时长推进时间（经时间插件 `dev.lifeloom.time.advance`；时长 0 不调用）。逻辑失败不耗时（不推进时间）。v1 执行为同步原子，由核心单逻辑线程保证串行。

推迟项（明确不在 v1）：排队与打断需要实时节拍与部分时间结算，随外壳 / 实时节奏接入细化；弹性动作的输入声明待 UI 成员；实例附着与“种”的动作集待实例成员；NPC 与玩家共用同一动作流待 NPC 成员。

状态：2026-09-13 实施（动作插件 v1，含单元测试；桌面外壳演示覆盖“注册 → 执行 → 时钟推进 15 分钟”全链路）。
