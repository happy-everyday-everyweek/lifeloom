# 地图空间模型：纯坐标、逐 Z 声明与分工

地图（空间模型）曾以“地点、地点间关系、实例的位置归属”表述（设计草案 v0.3）。对齐中明确：项目没有“地点”与“层”的架构概念——空间就是全局 XYZ 坐标（小数）；“层”只是玩家口语，指一块“地板”（物品类的特殊实例，声明一片水平承载面）所辖的空间段。本 ADR 固定空间模型口径。

决策一（坐标与空间声明）：空间为全局 XYZ 坐标（小数）。实例的空间占用以“空间声明”表达：逐 Z 单位、同一平面内的长方形；跨 Z 的长方体必须逐单位声明。默认一个实例的声明保持在一块；电梯/扶梯类特例允许多段；“0”不作为常规概念。

决策二（地板）：地板是一个特殊实例类型（物品分类下的种），声明一片水平承载面。不为此引入“层”实体。

决策三（分工）：地图持有坐标与声明、提供空间查询；地图渲染负责把空间数据绘成图形（不使用素材；默认形状+样式，支持画法钩子），产出经 UI 呈现；移动负责空间移动与移动管理，碰撞箱独立于绘制形状、归移动处理。

决策四（接口哲学）：钩子与事件必须多且足够细分，给插件开发留够空间；空间变化必须发事件。

推迟项：三成员契约草案（钩子与事件清单）、移动细节、地板与查询接口细节。
