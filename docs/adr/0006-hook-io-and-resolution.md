# 插件间调用协议：钩子输入 / 输出与钩子解析器

底层插件层（动作、时间、参数、NPC 等）之间的协作需要两类能力：一是调用时携带数据并取回结果（例如“把时间推进 N 分钟”并读到新时刻、“登记一个动作定义”）；二是对钩子调用本身做治理（禁用某个钩子、把调用替代到新钩子——支撑“禁用原钩子＋新建钩子”的推荐改法）。核心既有的无参钩子调用与广播式事件均不满足。

决策一（输入 / 输出）：钩子调用携带字符串输入并可回传字符串输出——钩子上下文（HookContext）增加 input 与 reply(output)；调用侧 PluginContext.invokeHook(钩子ID, 输入) 与核心同名重载返回输出。输入 / 输出格式由调用方与钩子约定（统一格式随底层插件层细谈推进）；原有无参调用保持兼容。

决策二（钩子解析器）：核心保留极薄的“解析器”原语——仅系统插件可注册（如钩子管理插件）；每次钩子调用前解析目标：直接执行 / 跳过 / 重定向；重定向沿替代链解析（限制链长、检测成环）。无解析器时行为与之前完全一致；解析器随其注册插件卸载 / 替换而移除。权限闸门在解析后对最终目标执行。解析器即“钩子管理”与核心调度的衔接口径（此前记为待细谈项）。

原因：贯彻极薄宿主与“一切功能皆插件”（ADR-0001）——治理钩子的策略放在插件里，核心只保留解析的发问点；调用数据通道是最小可用的协作原语，先以字符串落地，避免过早锁定结构化格式。

状态：2026-09-13 实施（M3 收尾），含单元测试。字符串格式的版本化、多解析器的优先级与结构化输入随插件细谈推进。
